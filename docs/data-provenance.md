# Data provenance

Every page this project evaluates on is generated by this repository. Nothing
here is a real document.

## SynthLayout

`forgesight/synth/generator.py` builds a page as a PDF with ReportLab, records
the exact rectangle of every element it draws, then rasterises that PDF with
pypdfium2 at the profile DPI. Because the ground truth is the drawing operation
rather than a label applied afterwards, the boxes are exact by construction.

**Content is generated, not sampled.** Text is assembled from a small in-repo
vocabulary (`forgesight/synth/textgen.py`) with a seeded PRNG — no copyrighted
corpus, no scraped text. Figures are drawn procedurally. Fonts are the ones
bundled with ReportLab.

**Every page is marked.** The word `SYNTHETIC` is drawn into the page, and the
provenance string `synthetic:forgesight-synth@1#seed=N,template=T` is stored on
the row and returned by the API. A screenshot of this data cannot be mistaken for
a real document.

## Versioning

| dataset | version | pages | use |
|---|---|---|---|
| `synth-clean` | 1 | 300 (60 calib / 240 test) | threshold selection, frozen test metrics |
| `synth-scan` | 1 | 240 (paired with the test split) | domain-shift quality |
| `synth-bench` | 1 | 200 (incl. 40 two-up) | performance benchmarks, tiling experiment |

A dataset version's `manifest_hash` is the sha256 of a canonical JSON listing
every `(page_sha, annotation_sha, split)`. It covers content only — deliberately
not the generated page id, which is an identity and would make the hash differ
on every run.

Two builds of the same dataset version with the same generator and the same
seeds produce the same hash; this is asserted rather than assumed
(`test_manifest_hash_is_reproducible_across_builds`). A different page count
produces a different hash, because it is a different dataset.

## Ground-truth validity

Checked per page, with thresholds, in `forgesight/synth/gt_validate.py`:

| rule | threshold |
|---|---|
| every box contains ink | ≥ 2% non-background pixels |
| ink coverage by boxes, excluding a 60 px margin | ≥ 99.5% |
| same-class box overlap | IoU ≤ 0.3 |

These are assertions in the test suite across all four templates and eight seeds
each, not a one-off check. Two real defects were found this way during
development: a `text_block` that dropped the ascent term and leaked every
descender outside its box, and a sign error on `descent` that pushed every text
box *upward*.

## The limitation that matters

**The synthetic box conventions are this repository's, not DocLayNet's.** Paragraph
granularity, where a table box stops and a caption box starts, what counts as one
`text` region — these are choices made here.

So the absolute mAP figures in any report are **not comparable with published
numbers**, and the report says so in its Limits section. What is meaningful is
the relative comparison between candidates on the same dataset, with the caveat
that a candidate which happens to suit the synthetic convention better could
score well here and worse on real pages. That caveat is printed on every report
and repeated here because it is the one thing a reader must not skip.

## What is not here

- No DocLayNet page, or any other real-document dataset.
- No employer or client data, of any kind.
- No image with a recognisable person or a third-party copyright.

An optional local-only DocLayNet sanity subset was considered for a later phase
and is deliberately deferred. It is CDLA-Permissive-1.0, and it may overlap the
evaluation data of the two models used here — see the technical report
(arXiv:2509.11720) — so it would be a weak sanity check rather than a headline
metric.

## Reproducing

```bash
make datasets
```

Manifest hashes are printed. Two runs on the same generator version print the
same hashes.
